## 2026-10-05 — 修复打包版站方功能失效

### 现象

悬浮窗点「校准」报红色错误：

```
站方刷新失败：导出失败: No module named 'session_join'
```

点「打开网页看板」→ 浏览器打开失败（127.0.0.1:8788 连接被拒）。

### 根因

exe 打包时**漏了整个 `proxy_monitor` 目录**。

站方相关功能依赖磁盘上的模块文件，打包时没带：

| 证据 | 结果 |
|---|---|
| 旧 exe 的 `Analysis-00.toc` 里 `proxy_monitor` 出现次数 | **0** |
| 旧 exe 的 `warn-*.txt` | `missing module named session_join / calib_export (delayed, optional)` |
| 旧 exe 的 CArchive toc | `proxy_monitor` 条目 **0 个** |

两条失效路径：

```
① 校准：trigger_proxy_refresh()
     → sys.path.insert(_get_proxy_monitor_dir())   ← 目录不存在
     → import session_join                          ← ModuleNotFoundError

② 网页看板：open_web_panel()
     → subprocess.Popen([py, "panel.py", "--port", "8788"], cwd=<不存在的目录>)
     → 子进程起不来 → 8788 无人监听 → 浏览器白页
```

主功能不受影响——该导入是 `delayed, optional`，失败被 try 吞掉了。

### 修复

**1. spec 把 `proxy_monitor` 打进 exe**

关键设计：打包时**先复制一份"干净副本"到临时目录**，剔除运行时数据后再作为 `datas` 源。

理由：原目录含 11MB `store.db`、152KB `poll.log`、`dsh_auth.json`（登录凭据）——
直接打包等于把本机数据塞进分发包。

排除项：
```
目录：__pycache__ / archive / 对账参考
文件：store.db / proxy_monitor.db / poll.log / proxy_calibration.json
     dsh_auth.json / last_retention.txt / sites.json / host_alias.json
     cache_prices.json / cost_ledger.json / calib_samples.json / site_merge.json / prices.json
后缀：*.pyc *.pyo *.log *.db *.db-wal *.db-shm
```

**2. `init_paths()` 加冻结版自愈**

exe 首次启动，若同级没有可用的 `proxy_monitor`：

- **优先复用本机已有的**（按 `store.db` 大小打分挑最全的）——不复制，只记日志
- 实在没有，才从 `_MEIPASS` 释放一份

⚠️ 第一版自愈是「直接释放」，结果造出个 2.7MB 的空表结构库，
校准读它算出**全是 0**。所以改成优先复用。

**3. `_get_proxy_monitor_dir()` 候选顺序重排**

按**数据价值**排，真实工作区提到 exe 同级之前：

```
① $HERMES_CACHE_PM_DIR          （显式指定，分发给别人时用）
② D:\Hermes works\proxy_monitor （本机真实工作区，有流水库）★
③ exe/脚本同级 proxy_monitor     （自愈释放的那份，库是空的）
④ WORK_DIR / %APPDATA%\HermesCacheMonitor 下的副本
```

### 踩的坑

**① 打包源目录不能直接用 `proxy_monitor/`**
里面有 11MB 流水库、日志、登录凭据。直接打包 = 把本机数据发出去。

**② 自愈释放会造出空库**
第一版直接 `copytree` 到 exe 同级 → 2.7MB 空表结构库 → 校准算出 0。
→ 改为「先复用真实目录」。

**③ `warn-*.txt` 报 missing 不一定是真问题**
`delayed, optional` 导入 + 运行时 `sys.path` 动态插入的组合，
PyInstaller 静态分析看不出来。**判断标准是实测 import，不是读 warn。**

**④ 打包环境与运行环境相反**
- **打包**用 MSIX Store 版 `python`（它有 pystray / PIL）
- **跑脚本**用 `py`（Store 版会把 `%APPDATA%` 重定向到影子目录）

**⑤ spec 不能依赖外部临时目录**
主工作区 spec 原本指向 `build/proxy_monitor_pack`，那个目录被清理后打包直接失败。
→ 改成 spec 自己 `tempfile.mkdtemp()` 生成干净副本，用完自动删。

**⑥ `__pycache__` 会混进 exe**
第一版过滤只写在 `datas` 源上，但 PyInstaller 会自己递归收集。
→ 改成本地干净副本后彻底干净。
