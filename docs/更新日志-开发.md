## 2026-10-09 — v1.3.0：界面重构 + 归集自愈

### 一、悬浮窗界面重构（用户驱动的多轮迭代）

用户提出的原始诉求：去掉系统标题栏（省 32px）、最小化/退出移入右键菜单、
精简模式改极简风、加「今日站点消费」。

**技术选型（每项都做了对照实测，不靠猜）：**

| 需求 | 实测结论 | 落地方案 |
|---|---|---|
| 无边框窗口 | `overrideredirect(True)` 后系统拉伸热区消失、需自写拖动 | 自写拖动 + 四边/四角热区 |
| 圆角 | DWM 属性 33 对 `overrideredirect` 窗口**有效**，且**自带淡阴影** | `apply_round_corners()` |
| 老式阴影 | `CS_DROPSHADOW` / `ExtendFrameIntoClientArea` 在半透明无边框窗口上**无效** | 弃用，靠 DWM 自带 |
| 右键菜单白边 | tk.Menu 在 Windows 上有 **2px `#f0f0f0` 外框**；改 `bd`/`activeBorderWidth`/类画刷/窗口样式**全部无效** | 自绘 `DarkMenu`（无边框 Toplevel） |
| 托盘菜单深色 | uxtheme 私有 ordinal 135/136 可把原生菜单从 `#f9f9f9` 变 `#2c2c2c` | `force_dark_menus()` |
| 透明度下限 | `-alpha` 只作用于被设置的窗口，**不传染子 Toplevel** | 子窗口天然不透明，无需处理 |

**踩坑（都已修，写在这里防复发）：**

1. **拖动"只有文字的地方能拖"** —— Tk 的 `<B1-Motion>` 发给**鼠标指针当前所在控件**，
   不是按下的那个。只给 Label 绑事件，指针一离开文字就断。
   → 同时绑顶层窗口 + 所有子控件。

2. **拖动位移被累加（拖 80px 跑 155px，甚至飞出屏幕）** ——
   `geometry()` 请求不立即生效，连续 Motion 里读 `winfo_x()` 拿到的是**旧值**，
   于是每帧把整个位移量再加一遍。
   → 起点位置**在按下时记一次**，Motion 里用自己维护的值算。

3. **拉伸同样累加 + 尺寸无上限** —— 同一个坑的另一半；另外没夹尺寸上限，
   实测能把窗口拉到 2420x1486（屏幕才 2560x1440），视觉上"窗口跑没了"。
   → 起点记一次 + 尺寸/位置双向钳制。

4. **尺寸记忆"宽度还是继承"** —— 切换模式时程序主动改尺寸，但 Tk 会先发
   **旧尺寸的 Configure 事件**，把刚写进去的 `full_w` 立刻覆盖掉。
   → 切换期间挂 250ms 闩锁丢弃过渡事件。

5. **尺寸下限两套标准打架** —— 拉伸热区用 240，切换模式处硬编码 `max(300,…)`，
   导致手动能缩到 240、一切换就被抬回 300。
   → 收拢成 `_MIN_W` / `_MIN_MINI_H` / `_MIN_FULL_H` 一组常量，三处共用。

6. **透明度改完重开菜单弹回 100%** —— 两个原因叠加：
   ① `Scale.set()` **会触发 command 回调**（等于每次弹菜单都重置一次）；
   ② 初值是程序启动时算死的。
   → 初值传 callable（每次现取）+ 先 `set()` 再挂 `command`。

7. **双击被触发两次** —— `<Double-Button-1>` 会**冒泡到 root**，子控件和 root
   都绑了回调 → 一次双击调两遍。"双击切模式"因此一直是坏的（切过去又切回来）。
   → 回调 `return "break"` 阻断冒泡。

8. **子窗口标题栏 3 个是白的** —— 建窗时立刻调 `apply_dark_title_bar` 不生效
   （价格配置/提示注入/实付录入，实测 `#f3f3f3`）。
   **不是** `resizable/transient` 导致的（做了对照实验，猜错了）。
   真因是**时机**：DWM 深色标题栏属性要在窗口被映射后才认。
   → 延迟 120ms + 400ms 各重设一次。

9. **子窗口表格白底** —— Treeview 走系统默认 ttk 主题（winnative/vista）。
   → 切 `clam` 主题 + 自定义 `Dark.Treeview` 样式。

10. **成本行单击误触** —— 改成双击弹价格窗。注意 Tk 双击会先发两次单击，
    必须**摘掉单击绑定**，否则单击就弹窗。

### 二、站点用量归集自愈（用户换入口域名后统计不上）

**现象**：用户 03:24 把 dshapi 从 `api2` 换到 `api9` 入口，之后面板数字卡在 03:13
不动。采集**完全正常**（库里 05:04 还有新流水），问题出在归集。

**根因（两条路同时断）**：

```
① Hermes 记录的 billing_provider 退化成裸 `custom`
   （换地址后名字丢了，只剩通用默认名）
   → sites.json 登记的是 `custom:your-provider`，映射不上
② 新的 billing_base_url = api9.dshapi.icu
   不在 sites.json 的 bases 里（那里只有 api2 / api）
   → 按域名兜底也认不出
```

实测：1627 条流水 `match_kind=none`，今日归集率 47%。

**修复（三层）**：

1. **域名优先识别**（`session_join.py`）
   - 新增 `main_domain()`：取主域名（`api9.dshapi.icu` → `dshapi.icu`），
     IP/localhost 原样返回不折叠
   - 新增 `load_domain_map()` / `find_site_by_domain()`：站点配置里所有地址
     （base_url + bases）的主域名进索引。**唯一命中才认**，多候选不猜
   - 归集时顺序改为「**先域名（硬事实）→ 再 provider 名（可能已退化）**」

2. **健康检查 + 一键补登**（新增 `join_health.py` + 面板）
   - `join_health.report()`：算今日归集率、列出认不出的地址
   - 面板顶部状态条：正常显示 `✅ 用量归集正常 N/N`；
     异常时写明「地址 X 没登记（N 条）」+「补登到 Y 站」按钮
   - `site_admin.add_base_domain()`：补登（幂等、备份、原子写、补完自动重跑归集）

3. **站点配置页**（面板新增 tab）
   - 可改 bases / providers / proxy / label，每字段配人话说明
   - `site_admin.edit_site()`：只改传入字段，写盘走备份+原子替换

**顺手修的坑**：加站表单的「备选地址」输入框**填了不生效** ——
代码只把它写进 note 文字（"请在 sites.json 的 bases 字段补充"），
没写进 `bases`。现在真落盘了。

**修复效果**：本会话 64 条 → **399 条**；今日归集率 47% → **100%（830/830）**。

## 2026-10-05 — 修复打包版站方功能失效

### 现象

悬浮窗点「校准」报红色错误：

```
站方刷新失败：导出失败: No module named 'session_join'
```

点「打开网页看板」→ 浏览器打开失败（127.0.0.1:8788 连接被拒）。

### 根因

exe 打包时**漏了整个 `proxy_monitor` 目录**。

站方相关功能依赖磁盘上的模块文件，打包时没带：

| 证据 | 结果 |
|---|---|
| 旧 exe 的 `Analysis-00.toc` 里 `proxy_monitor` 出现次数 | **0** |
| 旧 exe 的 `warn-*.txt` | `missing module named session_join / calib_export (delayed, optional)` |
| 旧 exe 的 CArchive toc | `proxy_monitor` 条目 **0 个** |

两条失效路径：

```
① 校准：trigger_proxy_refresh()
     → sys.path.insert(_get_proxy_monitor_dir())   ← 目录不存在
     → import session_join                          ← ModuleNotFoundError

② 网页看板：open_web_panel()
     → subprocess.Popen([py, "panel.py", "--port", "8788"], cwd=<不存在的目录>)
     → 子进程起不来 → 8788 无人监听 → 浏览器白页
```

主功能不受影响——该导入是 `delayed, optional`，失败被 try 吞掉了。

### 修复

**1. spec 把 `proxy_monitor` 打进 exe**

关键设计：打包时**先复制一份"干净副本"到临时目录**，剔除运行时数据后再作为 `datas` 源。

理由：原目录含 11MB `store.db`、152KB `poll.log`、`dsh_auth.json`（登录凭据）——
直接打包等于把本机数据塞进分发包。

排除项：
```
目录：__pycache__ / archive / 对账参考
文件：store.db / proxy_monitor.db / poll.log / proxy_calibration.json
     dsh_auth.json / last_retention.txt / sites.json / host_alias.json
     cache_prices.json / cost_ledger.json / calib_samples.json / site_merge.json / prices.json
后缀：*.pyc *.pyo *.log *.db *.db-wal *.db-shm
```

**2. `init_paths()` 加冻结版自愈**

exe 首次启动，若同级没有可用的 `proxy_monitor`：

- **优先复用本机已有的**（按 `store.db` 大小打分挑最全的）——不复制，只记日志
- 实在没有，才从 `_MEIPASS` 释放一份

⚠️ 第一版自愈是「直接释放」，结果造出个 2.7MB 的空表结构库，
校准读它算出**全是 0**。所以改成优先复用。

**3. `_get_proxy_monitor_dir()` 候选顺序重排**

按**数据价值**排，真实工作区提到 exe 同级之前：

```
① $HERMES_CACHE_PM_DIR          （显式指定，分发给别人时用）
② D:\Hermes works\proxy_monitor （本机真实工作区，有流水库）★
③ exe/脚本同级 proxy_monitor     （自愈释放的那份，库是空的）
④ WORK_DIR / %APPDATA%\HermesCacheMonitor 下的副本
```

|---|---|
| 新 exe CArchive 里 `proxy_monitor` 条目 | **19 项** ✅ |
| exe 内 `APP_VERSION` | **1.2.0** ✅ |
| 隐私泄漏（`d1api` / `empty city` / `ds2` / `c003`） | 各 **0** 次 ✅ |
| 数据泄漏（`store.db` / `sites.json` / `dsh_auth.json`） | 均未进包 ✅ |
| exe 启动日志 | `复用 D:\Hermes works\proxy_monitor（store.db 12238848 字节）` ✅ |
| `session_join` 归集 | 跑通 ✅ |
| `calib_export` 导出 | **22 个会话 / 6 天日度** ✅ |
| `panel.py --port 8788` | HTTP 200，19258 字节页面 ✅ |
| 发布前体检 | ✅ 通过 |
| `git add` 干跑 | 只加 `dist/README.md`，exe 未进 ✅ |

### 踩的坑

**① 打包源目录不能直接用 `proxy_monitor/`**
里面有 11MB 流水库、日志、登录凭据。直接打包 = 把本机数据发出去。

**② 自愈释放会造出空库**
第一版直接 `copytree` 到 exe 同级 → 2.7MB 空表结构库 → 校准算出 0。
→ 改为「先复用真实目录」。

**③ `warn-*.txt` 报 missing 不一定是真问题**
`delayed, optional` 导入 + 运行时 `sys.path` 动态插入的组合，
PyInstaller 静态分析看不出来。**判断标准是实测 import，不是读 warn。**

**④ 打包环境与运行环境相反**
- **打包**用 MSIX Store 版 `python`（它有 pystray / PIL）
- **跑脚本**用 `py`（Store 版会把 `%APPDATA%` 重定向到影子目录）

**⑤ spec 不能依赖外部临时目录**
主工作区 spec 原本指向 `build/proxy_monitor_pack`，那个目录被清理后打包直接失败。
→ 改成 spec 自己 `tempfile.mkdtemp()` 生成干净副本，用完自动删。

**⑥ `__pycache__` 会混进 exe**
第一版过滤只写在 `datas` 源上，但 PyInstaller 会自己递归收集。
→ 改成本地干净副本后彻底干净。
