> 上一篇：`01-加站与自动化体检指南.md`（讲的是**探测原理**与命令行加站）
> 本篇讲的是**界面加站**——拿 exe 的人不用碰 JSON 也能加站。

---

## 一、加站：点界面就行，不用改 JSON

### 入口

网页顶部工具栏 → **＋ 加站**（蓝色按钮）

### 三步流程

```
① 填地址        api.xxx.com  （只填域名就行）
       ↓  点「探测 →」
② 看探测结果    识别为 NewAPI ／ sub2api ／ 官方站 ／ 无法识别
       ↓
③ 补两栏确认    别名（可空） + provider 名（可空）
       ↓  点「✓ 确认加站」
   ✓ 写入 sites.json（自动备份上一版）
```

### 地址怎么填？只填域名，程序自动补

| 你填的 | 存进去的 | 说明 |
|---|---|---|
| `api.xxx.com` | `https://api.xxx.com/v1` | 补协议 + 补 `/v1` |
| `https://api.xxx.com` | `https://api.xxx.com/v1` | 补 `/v1` |
| `https://api.xxx.com/v1` | `https://api.xxx.com/v1` | 已有后缀，不动 |
| `http://1.2.3.4:8080` | `http://1.2.3.4:8080/v1` | 端口结尾，补 `/v1` |
| `https://x.com/api/v1` | `https://x.com/api/v1` | 含 `/api/`，保守不补 |

**为什么补 `/v1`**：绝大多数中转站是 OpenAI 兼容形态，`base_url` 带 `/v1` 才能拼出
`/v1/usage`、`/v1/chat/completions` 这些接口。判不准的情况（路径含 `/api/`）宁可不补，
免得拼出 `/api/v1/v1` 这种错地址。

### provider 名：从下拉里挑，程序已经帮你找好了

探测完地址后，界面会**自动从 Hermes 的 `config.yaml` 读出所有 `custom:` 开头的 provider**，
并按域名匹配把「最可能是这个站」的排在前面、默认勾选。

| 显示 | 含义 |
|---|---|
| 带 ✓ 的标签 | 域名匹配上的，通常全选即可 |
| 灰色标签 | 其他所有 provider，需要时手动勾 |
| 手输框 | 也能自己填，多个用逗号分隔 |

**为什么必须填**：`hermes_providers` 是采集器**拿 API key 的来源**。留空的后果是
采集器没有 key → 这个站采不到任何数据 → **用量页不会显示它**（实测踩过）。

> sub2api 站留空的后果轻一点（还能靠登录态采），但仍建议填上，否则拿不到余额/倍率。

## 二、探测结果怎么看

| 探测结果 | 界面表现 | 下一步 |
|---|---|---|
| **NewAPI** | ✅ 绿色 | 直接加。用 API key 采集，**不需要账号密码** |
| **sub2api** | ✅ 绿色 + 黄字提示 | 直接加。加完**要去站点账号页填账号密码**才能拿逐条流水 |
| **official** | 🚫 红色 | **挡住，不给加**。官方站（DeepSeek/OpenAI/OpenRouter）用量在各自后台看 |
| **unknown** | ⚠️ 黄色 | 给下拉框手动选 NewAPI / sub2api，或先留空（可后补） |

### unknown 的三种原因

1. **非标准中转站** —— 自建服务、改造过的站，本来就没这些特征接口
2. **地址写错了** —— 最常见。检查域名拼写、有没有多写路径
3. **要登录才暴露特征** —— 少数站的无鉴权接口不返回特征字段

### 重复添加会被拒绝

探测时会检查这个域名是否已在监控里，是的话红字警告 + **不给下一步**。

> 同一个站的不同域名入口（`api` / `api2`）算**同一个站**，不要重复加 ——
> 用 `sites.json` 的 `bases` 字段配多域名故障切换。这一点界面暂时帮不上，
> 需要手工在 JSON 里补 `bases` 数组。

## 三、多站登录态（2026-10-07 新增）

### 以前只能管一个站

`dsh_auth.json` 是**平铺的单站结构** —— 第二个 sub2api 站进来时没地方放 token，
界面上会显示「登录态槽位被 X 占用」。

### 现在每个站有独立槽位

存储结构改成按站分片：

```json
{
  "sites": {
    "api.dshapi.icu": { "access_token": "...", "refresh_token": "...", "email": "..." },
    "api.tryaigc.cn": { "access_token": "...", "refresh_token": "...", "email": "..." }
  },
  "active": "api.dshapi.icu"
}
```

**旧的平铺格式会在首次读取时自动迁移**（幂等，只发生一次），不会丢 token。

### `active` 是什么

`active` 指向"当前站"，影响**不传 host 参数的老调用**（比如采集器）。规则：

- 新加/新登录一个站 → 自动设为 active
- **给别的站续期 token 不会改 active**（否则老代码会串到那个站去 —— 实测踩过这个坑）
- 想手动切：`dsh_auth.set_active("host")`

### 站点账号页怎么看

每个 sub2api 站**各报各的状态**：

| 状态 | 含义 |
|---|---|
| 登录态正常 剩 N 小时 | 这个站有自己的 token 且未过期 |
| 登录态失效 | 有 token 但过期了 |
| 尚未登录 | 这个站还没填过账号密码 |
| 无需登录态 | NewAPI 类站，用 key 采集 |

## 四、怎么停掉一个站（不删数据）

站点账号页每张卡片右上角有 **停用 / 启用** 按钮。

- **停用**：不再采集，历史数据全部保留，随时可恢复
- **没有「删除」按钮**（故意的）

**为什么不给删**：删一个站要同时清理 4 处，漏一处就留脏数据 ——

1. `sites.json` 的站点条目
2. `_probe_cache` 里对应键
3. `store.db` 的 `usage_flows` 表
4. `store.db` 的 `flow_sessions` / `site_accounts` / `collect_state` 表

真要删，手工来，删前先导出备份。

## 五、加站的可靠性设计（为什么敢让它自动写文件）

| 措施 | 作用 |
|---|---|
| **写前自动备份** | 每次改 `sites.json` 前，上一版存成 `sites.json.bak` |
| **原子替换** | 先写 `.tmp` 再 `os.replace()` —— 中途断电不会留半截文件 |
| **域名去重** | 同 host 已存在直接拒绝，**绝不覆盖** |
| **格式校验** | 地址必须 http(s) 开头、域名合法，否则拒绝 |
| **探测结果回填** | 探测到的 kind 一并写入配置 + 缓存，省得下次重探 |
| **unknown 不固化** | 探不出来就**不写 kind**，留给加载时重探（避免把"探不出"永久写死）|

**凭据永远不进 `sites.json`** —— 账号密码存在独立的 `credentials.json`（已排除在
开源同步外），两套文件互不越界。

## 六、已知边界与坑

### 探测可能慢（3~10 秒）

探测要试 2~3 个特征接口，**不存在**的接口只能等超时。已优化：

- `/api/status`（NewAPI 特征）**先探** —— 它是轻量接口，存在的话 1 秒内返回
- 原本 `/v1/sub2api/billing` 排第一，不存在的路径会硬等 10 秒 → 已调整顺序 + 超时压到 3 秒
- 实测：NewAPI 站 20 秒 → **9.7 秒**；官方站 **0.005 秒**（本地规则直接判，不联网）

> 如果探测老是慢，说明该站两个特征接口都不存在 —— 属于判不出的站，
> 界面上手动选 kind 就行。

### 加站后要重启吗？**不用**

`site_resolver` 带 mtime 缓存，配置改了自动重读。下一个 5 分钟采集周期就会带上新站。
（界面上勾了「加完立刻采一次」的话，马上就能看到数据）

### 加完站发现没数据？

1. 检查探测出的 kind 对不对（站点账号页能看到）
2. NewAPI 站：确认 `hermes_providers` 里的 provider 名拼对了 —— key 是从 Hermes
   `config.yaml` 现读的
3. sub2api 站：**必须去站点账号页填账号密码**，否则只有聚合数、没有逐条流水
4. 看 `poll.log` 或页面顶部告警

### favicon 404

浏览器控制台会有一条 `favicon.ico 404` —— **无关紧要**，纯噪音，不用管。

### ⚠️ 一个站连不上会拖死其他站（串行采集的固有缺陷）

**实测踩过**（2026-10-07）：`example.com` SSL 握手超时，采集器在它上面反复重试
**9 分钟没出来**，排在后面的 `api.tryaigc.cn` 一直没轮到 → 新加的站看起来"没反应"。

**判断方法**：看 `poll.log` 或手动跑 `python site_collect.py`，如果某个站报
`handshake operation timed out` / `RemoteDisconnected`，就是它卡住了。

**临时解法**：单独采某个站 ——

```bash
python site_collect.py --site api.tryaigc.cn
```

**根治方向**：改成并发采集 + 每站独立超时（未做，记在待办里）。

> 注意：站连不上**不代表配置错了**。`example.com` 的网络问题是外部因素
> （被墙 / 站点故障 / 代理没走对），跟加站流程无关。
