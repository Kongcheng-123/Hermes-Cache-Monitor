## ⚠️⚠️ PowerShell 5.1 脚本编码坑（踩过，静默失败）

### 现象

往 `hermes_autostart.ps1` 加了段代码，路径 `D:\Hermes works\proxy_monitor`
**明明存在**，脚本却输出 `proxy-monitor not found:`。

### 根因

> **PowerShell 5.1 默认按 GBK 读 .ps1 文件。**

脚本文件是 **UTF-8 无 BOM** → 中文路径 `Hermes works` 被按 GBK 解读 → 读成乱码 →
`Test-Path` 判定不存在。

**这是静默失败**：不报错，只是路径找不到，很难往编码方向想。

### 处置（已根治）

把整个 ps1 存成 **UTF-8 with BOM**：

```python
raw = open(p, 'rb').read()
txt = raw.decode('utf-8')
open(p, 'wb').write(b'\xef\xbb\xbf' + txt.encode('utf-8'))
```

辅助手段：路径用 `Join-Path $PSScriptRoot "proxy_monitor"` 拼，
`$PSScriptRoot` 不依赖文件里写死的中文路径。

### 通用规则

**凡是被 PowerShell 执行的 .ps1，只要内容含中文路径，就必须存成 UTF-8 with BOM。**

## 进程管理常用命令

```bash
# 找进程（注意用 python3.12.exe，别只用 *poll_loop* 模糊匹配）
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='python3.12.exe'\" | Where-Object { \$_.CommandLine -like '*poll_loop*' -or \$_.CommandLine -like '*panel*' } | Select-Object -ExpandProperty ProcessId"

# 停（改代码后必须重启才生效 —— 旧进程会继续写旧口径数据）
powershell -NoProfile -Command "Stop-Process -Id <PID> -Force"
```

⚠️ 面板进程改了代码**必须重启**才生效。

⚠️ 进程可能包在 bash 里（`bash.exe -lc "... python poll_loop.py ..."`），
用 `Get-CimInstance` 按 CommandLine 找才找得全。
